## Production invariants established

1. `schools` is the tenant root.
2. Global user identity is separate from school membership.
3. One user can belong to multiple schools.
4. One school membership can hold multiple actor roles.
5. School-owned cross-entity relationships carry `school_id`.
6. Composite foreign keys prevent cross-school parent references.
7. Academic labels are configurable rather than hard-coded.
8. Authentication credentials are deferred until credential semantics are explicitly designed.
9. No student, biometric, attendance, or terminal model has been guessed into the foundation.

## Migration rule

CASA School uses Drizzle v1 migration folders.

The initial production migration is the first immutable migration directory generated by `drizzle-kit generate`. In the installed Drizzle version it has the form:

`drizzle/YYYYMMDDHHMMSS_school-foundation/migration.sql`

with the corresponding `snapshot.json` in the same directory.

The migration directory order plus Drizzle snapshots form the schema history. CASA School does not depend on a literal `0000_` filename.

CASA School uses `drizzle-kit generate` and `drizzle-kit migrate`.

`drizzle-kit push` is not part of the production workflow.
